# 关卡背景（美术装饰）设计方法论与红线

本文总结 `wellcooked_demo` 第 1 关背景从 0 到定稿的十几轮迭代，抽出可复用到 2/3/4 关的做法和不能碰的底线。

背景 = `layout_*.tsv` 里的 `art` 行。它不参与碰撞、不参与堆叠检测，但**会**直接影响观感与"像不像一关游戏"。

---

## 1. 方法论：六步

### 步骤 1 — 先拆组，再移植
从示例关卡（`s_test_level`）把背景拆成"装饰组"，以组为最小搬运单位，而不是逐个道具搬。

实测拆出来 3 类组：

| 组 | 构成（相对桌面中心） | 来源 |
|---|---|---|
| 餐桌组 A | `restaurant_table_01` + 2×`restaurant_chair_04`（±1.4 m）+ 桌面 `restaurant_plate_01` | `Art/Decoration` |
| 餐桌组 B | `restaurant_table_02` + 2×`restaurant_chair_03`（±1.4 m）+ 桌面 `decoration_table_plant` | `Art/Decoration` |
| 墙面装饰 | 竖招牌 / 香料架 / 票夹，高度 1.52 / 1.43 / 1.29 m | `Art/Decoration` |

拆分脚本：`extract-decor-groups.py`，产物 `testlevel-decor-groups.json`。

> 为什么不逐个搬：单个道具没有语义。桌子和它的两把椅子是"一个就餐位"，拆开摆就会出现"椅子孤零零摆在路中间"。

### 步骤 2 — 一关一套主题
一关只用一套主题素材目录（L1 = `city_sushi`）。主题一致性优先于素材多样性。

### 步骤 3 — 固定分层顺序
从下到上、从远到近，五层：

```
地面（街面 → 室内地板）
  └ 墙（单面，连续）
      └ 墙面装饰（离墙 1 格，朝屋内）
          └ 室内家具组（餐桌组）
              └ 墙外街景（消防栓 / 井盖 / 长椅 / 车）
```

每层只引用上一层的边界参数（墙线、房间包围盒），不互相试探。

### 步骤 4 — 一切尺寸来自实测
- 尺寸表：`D:\oc2-level-build\art-sizes.tsv`（2270 行，Unity 实跑 bundle 量出来的包围盒）
- 落地：`y = -minY`（模型原点不在底部，直接放 y=0 会陷进地里或悬空）
- 桌面摆件：`y = 桌面高 + (-minY)`（例：盘 0.63、小盆栽 0.77）
- 格坐标：1 格 = 0.6 m；占地格数 = `ceil(宽 / 0.6)`

### 步骤 5 — 参数化生成，不手摆
用脚本（`make-background-l1-v10.js`）生成 art 行，脚本里只留参数：

- 墙线：台面外 2 格
- 墙延伸：左右各到 `X0−44 … X1+44`
- 餐桌排：贴厨房两侧，行距 8 格 / 17 格，同排组间距 9 格
- 街景：只列白名单，逐个写死坐标
- 车/大件：单独一行，注明是否在画面内

### 步骤 6 — 构建 → 进关 → 截图 → 改参数
一轮迭代约 6 分钟（构建 5 分钟 + 进关截图 1.5 分钟）。每次只看一件事：墙角 / 地面接缝 / 穿模 / 遮挡 / 取景。

## 2. 每层的规则与推荐参数

### 2.1 地面
- **先整片铺街面**（`exterior_path_01`，2.4 m，4 格步进，外扩 24 格），**再叠室内地板**（+0.02 m 抬高）
- 抬高是为了避免与街面 z-fighting；先铺后叠才不会有"两圈地面之间的空档"
- 禁止：只铺室内、或室内/街面各铺一圈留过渡带 → 会露出模板自带米色棋盘格

### 2.2 墙
- **只做单面墙**（第 1 关是北面）。多面墙必然出现转角拼接问题（半截缺口、重叠、错位）
- **连续封闭**，两端延伸到画面外（第 1 关 `X0−44 … X1+44`，58 段）
- **不用窗片/玻璃件**：墙要"实"。需要窗时只在台面范围连续铺同一种窗件，不要"1.2 m 砖墙 + 2.4 m 窗"混排（会形成一排砖柱）
- 墙段中心算法：`段起点 + 段宽/2`（之前用 `+宽/2−1` 导致 1.2 m 与 2.4 m 段沿线错半格、出现豁口）

### 2.3 墙面装饰
- 离墙线**内退 1 格**（0.6 m），朝向屋内：西墙 `yaw 270`、东墙 `90`、北墙 `180`
- 高度照抄示例：招牌 1.52、香料架 1.43、票夹 1.29
- 不要正好压在墙线上（会插进墙里）

### 2.4 室内家具组（餐桌组）
- 一组 = 桌子 + 2 椅（±3 格）+ 桌面摆件（盘 0.63 / 盆栽 0.77）
- 排布：贴厨房两侧各两排（第 1 关 `X0−8` / `X0−17`）
- **行距 ≥ 8 格（4.8 m），同排组间距 ≥ 9 格（5.4 m）**；更密就会椅子打架
- 椅子不得越过墙线：外排起点要按 `WZ1 − 6` 截断

### 2.5 墙外街景
- 只放**低矮、能从墙顶看到**的东西（井盖、消防栓顶部）
- 数量克制：消防栓 ×2、井盖 ×1、长椅 ×2 即可
- 大件（车 1.78 m、长椅 0.87 m）放墙外会被 2 m 高的墙完全挡住 → 要么放画面内，要么放到画面外（只作为"存在感"）

## 3. 红线（做不到就不要交付）

| # | 红线 | 后果 |
|---|---|---|
| R1 | **不许穿模**：任意两个 art 件占地不得相交，桌椅间距按实测留 ≥0.6 m | 观感立刻崩，用户第一次就否 |
| R2 | **不许压玩法**：art 不得覆盖台面、灶台、料箱、盘堆、出生点、通行格 | 影响可玩性与寻路 |
| R3 | **不混主题**：一关只用一套主题目录 | 风格割裂 |
| R4 | **不许悬空**：`y = -minY`；桌面摆件按桌面高度累加 | 悬空/陷地 |
| R5 | **地面不露底**：整铺 + 叠加，不得出现棋盘格空档或接缝 | 一眼看出是拼的 |
| R6 | **墙不露空**：连续、延伸到画面外；不出现半截墙、转角缺口 | 用户第二次就否了 |
| R7 | **不用"窗片"当墙**：`p_dlc07_WallWindow`、`p_dlc07_RestaurantWindow` 等是嵌入式窗片，单独摆会悬空/看不见 | 白做一轮 |
| R8 | **过滤异常尺寸**：>8 m 的平面件，或 `197×296 m` 这类数据异常件，不得进场景 | 整关取景被撑爆 |
| R9 | **墙后不放矮件**：2 m 墙挡住 1.8 m 以下物体 | 放了也看不见，浪费 |
| R10 | **不放人物**（当前约定）：NPC 全去 | 用户明确要求 |
| R11 | **大面积不用高饱和素材**：地板/墙只用灰、砖、石等低饱和件 | 荧光绿地板被否过 |
| R12 | **单一数据源 + 幂等**：art 行只由脚本生成；重跑前先剥离旧 `art` 行，玩法行原样保留 | 手改 tsv 会被下一次重跑覆盖 |
| R13 | **构建必须过自检**：`duplicates=0 badSpawns=0 overlaps=0`，否则不部署 | 坏关卡进游戏 |

## 4. 可见范围与取景常识

- 相机取景 ≈ 玩法物体包围盒 + 边距；1920×1080 下横向约 **±14 格**、纵向约 **±6 格**
- 判断"画面外"：`|x − 中心| > 20 格` 或 z 超出墙线 10 格外
- 顶部左侧 **订单卡 HUD** 遮挡约 1/3 宽度、顶部 190 px → 西北角放了也白放
- 相机从南往北俯视：**北侧物体只要矮于墙高就是不可见的**

## 6. 交付前自检 8 条

1. `art` 行是否全部由脚本生成，玩法行是否未被动过（`diff` 只看新增 art 行）
2. 地面：整铺 + 室内叠加，无棋盘格空档
3. 墙：连续、两端出画面、无窗、无半截
4. 墙面装饰：离墙 1 格、朝向屋内、不插墙
5. 家具组：组内不穿模、组间不重叠、不越墙线
6. 墙外：只有白名单小件；大件确认可见性
7. 构建日志：`duplicates=0 badSpawns=0 overlaps=0`，三处部署成功
8. 进关截图：与上一版逐项对比，**除本次要求外没有任何变化**

## 8. 组合式生成器（v2）：从原语出发

`D:\oc2-level-build\make-bg-compose.js` —— 不再套"一面墙 + 两排桌子"，而是把背景拆成可组合的原语：

| 原语 | 做法 |
|---|---|
| **资产画像** | 只按实测尺寸自动分类：地面(flat) / 边界(boundary) / 地标(landmark) / 家具(furniture) / 小件(detail)。不写死素材名单，换主题自动换池子 |
| **占位网格** | 0.6 m 一格；任何摆放先查占位，与玩法物体（外扩 2 格净空）或已放艺术件冲突就换位置（对应 R1/R2） |
| **分区** | 室外地面整铺 → 室内地板叠加 → 可选材质带切出"区域感" |
| **边界** | 由边界类资产按各自实测宽度推进；**进深大的件自动后移**，不吃台面净空；可混用多种墙件形成高低错落 |
| **地标群** | 每关 2–3 个不对称锚点，按「1 大 + 2~4 中 + 1~3 小」组合，制造视觉焦点 |
| **家具带** | 左右环带各 2 排，间距 5.4–8.4 m 抖动、型号交替；被地标挡住时横移几格再试 |
| **小件散布** | 家具两侧撒细节，密度随距离外扩 |
| **遮挡规则** | 边界之外的物件必须高于边界，否则不放（R9） |
| **确定性随机** | 每关固定种子（L2=202 / L3=303 / L4=404），随时可复现 |

每关配置只声明"想要什么"（主题、边界候选、地标池、家具池、种子），不写坐标——坐标由规则和种子推出来。

已落地效果：

- **L2 海滩**：不对称地标群（棕榈/沙堡）+ 零散露台餐桌，天然的不对称
- **L3 夏日祭**：整排红白摊位做边界，边界之外只放过更高的树（遮挡规则生效），左侧一团紫色皮纳塔地标
- **L4 欧式老城**：`StandardWall / RestaurantWall / WideWall` 混排，边界出现高低错落的"街区天际线"
